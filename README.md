## Weather Agent

Источник — **Open-Meteo** (выбран в Phase 1 Architecture Review: без
API-ключа, щедрый бесплатный лимит, документированный прогноз на
несколько дней). Два HTTP-запроса за цикл:

1. геокодинг `WEATHER_LOCATION` (строка вроде `Almaty`) → координаты —
   выполняется один раз и кэшируется на время жизни процесса;
2. сам прогноз погоды по координатам.

Результат нормализуется в `{location, current: {temperature,
feels_like, condition, wind_speed}, forecast: [...]}` (TZ v4 §11) и
сохраняется в `weather_snapshots`. WMO weather-коды переводятся в
человекочитаемое описание на русском.

`WeatherAPI.com` как источник **weather alerts** (единственное, чего
нет у Open-Meteo) сознательно не добавлен — TZ и Phase 1 report
называют это опциональным расширением, добавлять только когда реально
понадобится.

## Установка / запуск / тесты

Без изменений с Phase 3 — см. предыдущие разделы истории коммитов.
Дополнительно в `.env` теперь имеет смысл заполнить:

```env
WEATHER_LOCATION=Almaty
```

(пустое значение — агент просто не запускается, с явным
предупреждением в логе, остальная система работает как раньше).

```powershell
pip install -r requirements.txt
python run.py
pytest -q
```

**51 тест, все проходят** (43 из Phase 2/3 + 8 новых: `WeatherAgent` на
`httpx.MockTransport` — успешный разбор ответа, кэширование координат
между вызовами, неизвестная локация, HTTP-ошибка с retry/backoff,
отсутствующее поле прогноза; плюс `run_and_record`).

### ⚠️ Что проверено по-настоящему, а что нет

Как и с Telegram в Phase 3: `open-meteo.com` тоже не входит в список
разрешённых доменов в этой среде разработки (подтверждено тем же
способом — мгновенный `403 Forbidden` от egress-прокси). Поэтому:

- вся бизнес-логика (`WeatherAgent.run()`, кэширование координат,
  разбор WMO-кодов, обработка ошибок) протестирована по-настоящему
  через `httpx.MockTransport` — без единого реального сетевого вызова;
- **реальный сбой сети я тоже воспроизвёл по-настоящему**: запустил
  `run.py` с `WEATHER_LOCATION=Almaty` в этой песочнице, получил
  настоящий `403` от заблокированного `open-meteo.com`, увидел, что
  агент 3 раза честно ретраит с backoff, затем корректно репортит
  `FAILING` в `agent_runs`, а всё остальное приложение (scheduler,
  единый lifecycle) при этом продолжает работать без сбоев.

**Тебе нужно самому один раз прогнать `python run.py` с реальным
`WEATHER_LOCATION`** и проверить `/weather` в самом Telegram — увидеть
настоящие цифры погоды, а не только "агент упал предсказуемо".

## Технический долг / сознательно не сделано в Phase 4

- Геокодинг кэшируется только в памяти процесса (не в БД) — при
  каждом перезапуске `run.py` он выполняется заново. Для одного
  статичного города это не проблема; если понадобится — можно
  закэшировать координаты в конфиге.
- `notify()` о резких изменениях погоды (TZ упоминает только "если
  API их предоставляет") — Open-Meteo alerts не отдаёт, поэтому этой
  логики нет и не может быть без добавления второго источника.
